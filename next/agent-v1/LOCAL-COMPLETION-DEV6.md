# dev.6 本地开发范围与交付边界

用户要求本轮持续完成，故以整条使用链核对，不以一个小版本或测试数量作为产品完成标准。此表只对应原项目中的候选代码；最终测试结果另见最新验证报告。

## 与旧版本相比必须真正成立的闭环

- 观察状态与全量来源依赖同一SQLite事务；依赖缺失、来源撤销或过期则不继续使用该观察。
- 跨流共享审批只允许使用已审摘要。原始私聊source的audience、publish权限保持原样，Code材料不能通过摘要路径进入社交创作。
- 摘要创作有独立精确授权，且最终作品仍需逐件审核。改摘要、原来源失效、改账号/动作/目标或过期均使旧准备/批准不可继续。
- B站撤销/刷新先建立保守hold，再撤销派生别名；持久写故障不能让旧作品重新获得投递资格。审批和发送前独立检查源头，不能只相信失效传播已完成。
- 可信Host评测器缺失时不能提交自报的全部通过成绩；冻结检查项本身不是评测已通过。
- 维护入口仅供可信Host，人审body或模型不能伪造维护授权与停止证明。归档保留数据，不能当作物理删除或备份。

## 容量与可恢复边界

现有候选主动设有容量上限，达到上限会拒绝新增并留待治理，不悄悄丢记录。Code热64、Outbox热2000、官方入站热2048；冷索引各4096。自我证据512、记忆/来源1024、学习队列1000、成长目录每类512、精确摘要创作授权512、记忆审核4096仍有限。旧记录缺少完结证明、残留claim/lease或结果unknown时拒绝冷归档。未引入自动物理清理、未经批准的迁移或“无限长期运行”承诺。

## 停在部署前的原因

本会话没有DSH正式管理工具，且没有本批正式升级/重启或真实账号、模型费用授权。候选默认Host禁用，enabled:false、initializeEmpty:false、dataRoot:null。未改活bundle、profile、软链接、HMR、maibot-bridge和生产库，也不运行旧默认构建。正式管理器可用并获本批升级指令后，才能执行安装与真实Host/认证HTTP/原生UI验收；真实平台和长期体验仍需独立场景验收。这里的本地链交付不等同于完整juebot产品已经培养完成。
