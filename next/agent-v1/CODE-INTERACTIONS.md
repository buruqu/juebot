# Code 人工提问与单次审批（dev.5，延续dev.4）

2026-10-29。此功能已接入离线候选，未接真实 QQ 或 DSH Host。它继续使用同一个 DSH Agent 和原来的等待请求，答复不会创建新任务或重跑旧任务。

## 实际使用合同

已验证管理员会在原私聊收到“任务、工作区、具体问题或工具输入、请求 ID、版本”的通知。通知与交互记录在同一个 SQLite 事务保存，统一走 Outbox；不会通过另一条发送路径绕过暂停、预算或出站检查。

审批通知分别给出以下两条命令，管理员选择其中一条发送：

```text
/code审批 <请求ID> <版本> 允许
/code审批 <请求ID> <版本> 拒绝
```

“允许”只允许这次具体工具调用，绑定原任务、实际 DSH 会话、工具名称及完整参数，不授予永久权限。无法展示完整内容时拒绝创建审批，不截断参数让人批准。执行前还会复查授权、工作区、实际策略及工具输入；拒绝不能被其他中间件改成允许。

问题通知带真实问题 ID、选项及可复制的答案格式。例如：

```text
/code答复 <请求ID> <版本> {"answers":[{"id":"真实问题ID","selected":["原选项标签"]}]}
/code答复 <请求ID> <版本> {"answers":[{"id":"真实问题ID","selected":[],"custom":"我的答复"}]}
```

多题须逐题回答；选项必须来自该题，单选题最多选一项。格式错误、旧版本、错请求、引用/媒体、群聊或其他人发来的答复都会拒绝，不会转给模型当开发任务。开关命令仍是精确全文 `/开启code`、`/关闭code`。

答复直接处理，绕过等待中的任务队列。Code 关闭后不能提交新任务，但仍能回答当前任务的问题；排队任务保持暂停。答复成功后，任务仍使用原来的输入，另保存该次已认证答复的事件 ID 和原始时间，供同一个任务后续通知或结果被动回复使用。普通消息、其他任务或开关命令不能替它刷新回复窗口。

## 期限、私密性与失败行为

- 默认任务总期限 5 分钟，包含人工等待；每次交互亦有期限。超时、SDK 取消、撤权或卸载会终结等待，迟答不能重新激活任务。没有 broker 时保持 dev.3 的 needs-review 行为。
- 题目、完整工具输入、答案和来源只保存在 Code 域并返回原管理员私聊，不进入社交记忆、B站学习或公共日志。不返回模型内部推理。
- QQ 官方被动回复仍按所选已认证事件的原始时间计算保守 5 分钟期限；不会把时间改为当前时间，也不会自动改主动发送。unknown 通知不重投，不因为管理员答复而伪造发送成功。
- 记录持久化失败时，不会批准。即使超时、取消或关闭发生在数据库只读/故障期间，原等待也会拒绝，计时器和监听会清理；没写成的 pending 留到重新打开后转 needs-review。
- 通道关闭即使写状态失败，也会等执行尾部全部结束后报告固定错误；保持失败 owner/gate 关闭。Host 必须等 close 返回或拒绝后再释放库，并通过受管理恢复重新打开应用，不能绕过 owner 或直接重放任务。

## 候选限额与后续

交互 payload JSON 最多 12000 字符，最多 8 题、每题 16 个选项；完整通知最多 16000 UTF-8 字节且最多 16000 字符。中文和 emoji 同样按字节检查。每任务同时一个等待，热区最多 64 条交互记录；已回答/过期记录也占名额，可按dev.5合同显式冷归档，不自动清历史。创建时为待答复的最坏转义文本预留容量，总状态及预留不超过 7 MiB。

dev.5新增[显式交互冷归档和异常会话弃用](CODE-MAINTENANCE.md)：完整保留原文/事件去重/投递事实，不自动重建等待或重放旧输入。热交互64、冷索引4096、回应事件4096，Code任务64/QQ入站2048/Outbox容量仍需后续保留策略。命令确认、文件回传、表单按钮及真实平台验收仍未完成。

本轮仅扩展后台及 QQ 文本合同，没有新增原生管理界面。正式账号证明、独占 SDK 接线、实际工作区权限和模型费用仍需验证；没有自动安装、登录、调用模型或部署。准确验证结果见项目 VERIFICATION-AGENT-DEV5.md。
